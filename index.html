1. Что такое Claude Code

Claude Code — это официальный интерактивный инструмент командной строки (CLI) от Anthropic. По сути это агент, который помогает решать задачи по разработке программного обеспечения: читать и писать код, запускать команды, искать по проекту, автоматизировать рутину и многое другое.

Главная особенность — у меня есть набор «инструментов» (tools). Каждый инструмент выполняет одно конкретное действие: прочитать файл, выполнить команду в терминале, найти текст, запустить подагента и так далее. Ниже я подробно разбираю каждый из них.

2. Работа с файлами

Эти инструменты позволяют мне читать, создавать и изменять файлы на вашем компьютере.

Read — чтение файла

Читает файл из файловой системы по абсолютному пути. Возвращает содержимое с номерами строк. Умеет работать не только с текстом:

  • читает изображения (PNG, JPG и т.д.) и показывает их визуально;
  • читает PDF постранично;
  • читает Jupyter-блокноты (.ipynb) вместе с выводом ячеек.

По умолчанию читает до 2000 строк, но можно указать конкретный диапазон, если файл большой.

Write — создание/перезапись файла

Записывает файл в файловую систему. Если файл уже существует — перезаписывает его целиком. Используется для создания нового файла или полной замены содержимого. Кстати, именно этим инструментом создан тот документ, который вы сейчас читаете.

Edit — точечное редактирование

Делает точную замену строки в файле: находит фрагмент old_string и заменяет его на new_string. Подходит для частичных изменений, когда не нужно переписывать весь файл. Перед редактированием файл обязательно нужно прочитать. Есть режим replace_all — заменить сразу все вхождения.

NotebookEdit — редактирование Jupyter-блокнотов

Специальный инструмент для работы с ячейками Jupyter-блокнотов: позволяет менять, добавлять или удалять отдельные ячейки.

3. Выполнение команд (Bash)

Bash — запуск команд в терминале

Выполняет команду в оболочке bash и возвращает её вывод. Это один из самых мощных инструментов. Что важно знать:

  • рабочая директория сохраняется между вызовами;
  • есть таймаут (по умолчанию 2 минуты, максимум 10 минут);
  • команды можно запускать в фоне (run_in_background) — они продолжают работать между ходами;
  • для работы с Git и GitHub используется этот же инструмент (через git и gh).

При этом для чтения файлов и поиска я предпочитаю специальные инструменты (Read, Grep и др.), а не cat или grep через Bash — так удобнее и надёжнее.

4. Поиск и исследование кода

ToolSearch — поиск инструментов

Часть инструментов загружается «отложенно» — известно только их имя, но не описание параметров. ToolSearch по запросу подгружает полные схемы нужных инструментов, чтобы их можно было вызвать. Например, чтобы воспользоваться веб-поиском или планировщиком задач, я сначала нахожу их через ToolSearch.

WebFetch и WebSearch — работа с интернетом

WebSearch — поиск в интернете по запросу. WebFetch — загрузка содержимого конкретной веб-страницы по URL. Вместе они дают доступ к актуальной информации, документации и материалам, которых нет в моих «знаниях».

5. Подагенты (Agent)

Agent — запуск специализированного агента

Позволяет запустить отдельного агента для сложных многошаговых задач. У каждого типа агента свой набор доступных инструментов и своя специализация. Основные типы:

  • general-purpose — универсальный агент для исследования сложных вопросов и поиска кода;
  • Explore — агент только для чтения, для широкого поиска по множеству файлов;
  • Plan — агент-архитектор для составления планов реализации;
  • claude-code-guide — отвечает на вопросы о самом Claude Code, Agent SDK и Claude API;
  • statusline-setup — настройка строки статуса;
  • набор агентов vercel:* — специалисты по деплою, производительности и архитектуре AI-приложений на Vercel.

Агент можно запустить в фоне или в изолированной копии репозитория (git worktree). Важная деталь: запуск нового агента — «дорогая» операция, поэтому без явной просьбы я стараюсь делать задачи сам.

6. Взаимодействие с пользователем

AskUserQuestion — уточняющий вопрос

Используется, когда я застрял на решении, которое действительно за вами: его нельзя вывести из запроса, кода или разумных значений по умолчанию. Показывает вам варианты ответа на выбор (с возможностью добавить свой). Именно этим инструментом я уточнял у вас формат документа и его объём перед тем, как начать.

EnterPlanMode / ExitPlanMode — режим планирования

Позволяют перейти в режим планирования (когда нужно сначала продумать стратегию, не меняя код) и выйти из него, представив готовый план на утверждение.

7. Планирование и фоновые задачи

ScheduleWakeup — отложенное возобновление

Планирует, когда мне «проснуться» и продолжить работу — используется в режиме /loop, когда задачу нужно выполнять самостоятельно с определённым ритмом. Например, периодически проверять состояние внешней задачи.

Cron* — расписания (CronCreate, CronList, CronDelete)

Управление запланированными удалёнными агентами, которые выполняются по расписанию (cron): создание, просмотр списка и удаление. Подходит для повторяющихся автоматических задач.

Task* — управление задачами (TaskCreate, TaskGet, TaskList, TaskOutput, TaskStop, TaskUpdate)

Набор инструментов для создания фоновых задач, получения их статуса и вывода, обновления и остановки. Позволяет запускать длительную работу и следить за её ходом.

Monitor — ожидание условия

Используется, чтобы дождаться выполнения определённого условия (например, завершения процесса), не блокируя работу.

EnterWorktree / ExitWorktree — изолированное рабочее дерево

Создаёт и закрывает отдельную копию git-репозитория (worktree), чтобы вносить изменения, не затрагивая основную ветку.

PushNotification и RemoteTrigger

PushNotification — отправка уведомлений. RemoteTrigger — запуск действий по внешнему событию. Это инструменты для интеграции с внешними системами.

8. Навыки (Skills) и слэш-команды

Навыки вызываются командой вида /имя-навыка. Это специализированные сценарии со своими знаниями. Перечислю основные.

Встроенные команды разработки

  • /init — создаёт файл CLAUDE.md с документацией по кодовой базе.
  • /review — ревью pull request'а.
  • /code-review — ревью текущих изменений на ошибки и упрощения; с уровнем ultra запускает глубокое многоагентное облачное ревью.
  • /security-review — проверка безопасности изменений в текущей ветке.
  • /simplify — упрощение и улучшение изменённого кода (без поиска багов).
  • /verify и /run — запуск приложения, чтобы убедиться, что изменения реально работают.
  • /loop — запуск задачи по повторяющемуся интервалу.
  • /schedule — создание и управление запланированными удалёнными агентами.
  • /claude-api — помощь в создании и отладке приложений на Claude API / Anthropic SDK.

Настройка окружения

  • /update-config — настройка харнесса через settings.json: разрешения, переменные окружения, хуки (автоматические действия).
  • /keybindings-help — настройка горячих клавиш.
  • /fewer-permission-prompts — уменьшение числа запросов на подтверждение за счёт списка разрешённых команд.
  • /statusline-setup — настройка строки статуса.

Экосистема Vercel

Большой набор навыков с префиксом vercel: для работы с платформой Vercel. Среди них:

  • deploy, status, env — деплой, статус проекта и управление переменными окружения;
  • ai-sdk, ai-gateway, chat-sdk — построение AI-функций, маршрутизация моделей, чат-боты;
  • nextjs, next-forge, turbopack, shadcn — помощь по Next.js, монорепозиториям, бандлеру и UI-компонентам;
  • vercel-firewall, vercel-functions, vercel-storage, vercel-sandbox — безопасность, серверные функции, хранилища, изолированный запуск кода;
  • workflow, marketplace, auth — устойчивые рабочие процессы, интеграции, аутентификация.

9. Память

У меня есть постоянная файловая память. В ней я сохраняю отдельными файлами важные факты: кто вы (роль, предпочтения), обратную связь о том, как мне лучше работать, контекст текущих проектов и ссылки на внешние ресурсы. Это помогает не терять важные детали между сессиями. При этом я не дублирую то, что и так есть в коде или истории Git.

10. Заключение

Набор инструментов Claude Code построен вокруг простой идеи: каждое действие — это отдельный, предсказуемый инструмент. Чтение и запись файлов, выполнение команд, поиск, веб-доступ, подагенты, планирование задач, навыки и память вместе превращают меня из «чат-бота» в полноценного агента, способного выполнять реальную работу по разработке от начала до конца — исследовать проект, вносить изменения, проверять результат и автоматизировать рутину.
