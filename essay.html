1.Что такое Claude Code и как он работает

Claude Code — это официальный инструмент от Anthropic, который позволяет общаться со мной (Claude) прямо в терминале вашего компьютера, в IDE (VS Code, JetBrains) или через веб-интерфейс.

Главное отличие от обычного чата: у меня есть инструменты (tools) — специальные функции, которые дают мне возможность реально работать с вашим компьютером. Я не просто отвечаю текстом, а могу:

  • Читать и редактировать файлы на вашем диске
  • Запускать команды в терминале
  • Искать по коду и интернету
  • Работать с Git и GitHub
  • Запускать другие AI-агенты для сложных задач
  • Запоминать информацию между разговорами

Как это выглядит на практике? Вы пишете: "Найди все баги в моём коде и исправь их" — и я самостоятельно открываю файлы, анализирую, вношу правки, запускаю тесты. Без копирования и вставки — всё происходит прямо в вашем проекте.

2.Работа с файлами: Read, Write, Edit

Это основа всего. Именно через файлы я взаимодействую с вашим проектом.

Read — прочитать файл

Открывает любой файл на вашем компьютере и показывает мне его содержимое с номерами строк. Я могу читать:

  • Любые текстовые файлы: .py, .js, .html, .json, .md и т.д.
  • Картинки (PNG, JPG, WebP) — вижу изображения визуально
  • PDF-файлы — постранично (до 20 страниц за раз)
  • Jupyter-блокноты .ipynb — вместе с результатами выполнения ячеек
Пример использования

Вы: "Посмотри, что не так в файле app.py"
Я читаю /home/user/project/app.py, нахожу ошибку в строке 42 и объясняю проблему.

Write — создать или полностью перезаписать файл

Создаёт новый файл или полностью заменяет содержимое существующего. Именно этот инструмент я использую, чтобы создать новый проект с нуля — написать все файлы конфигурации, исходный код, README.

Важно: перед перезаписью существующего файла я сначала его читаю — чтобы случайно не потерять ваши данные.

Пример

Вы: "Создай React-компонент кнопки"
Я создаю файл Button.tsx с полным кодом компонента, пропсами, стилями.

Edit — точечная правка без переписывания

Находит конкретный фрагмент текста в файле и заменяет его на новый. Это как Ctrl+H (найти и заменить), только умный — я понимаю контекст и делаю минимальные изменения.

  • Обычная замена: меняет первое вхождение
  • Режим replace_all: заменяет все вхождения (удобно для переименования переменной)
Пример

Вы: "Переименуй функцию getUser в fetchUser во всём файле"
Я нахожу все getUser и меняю на fetchUser — только в нужном файле, без риска задеть другие.

Совет чайнику: Вам не нужно ничего копировать или вставлять. Просто скажите мне что изменить — я сам найду файл, внесу правку и покажу результат.

3.Выполнение команд в терминале (Bash)

Bash — запустить любую команду

Выполняет команды в терминале и возвращает мне вывод. Это даёт мне возможность делать практически всё, что можно сделать в командной строке.

Что я умею через Bash:

  • Устанавливать зависимости: npm install, pip install, cargo add
  • Запускать тесты: pytest, jest, go test ./...
  • Собирать проект: npm run build, cargo build
  • Работать с базой данных, Docker, облачными сервисами
  • Запускать скрипты в фоне и наблюдать за выводом
Пример 1: Установить и запустить
# Вы: "Установи все зависимости и запусти проект"
npm install
npm run dev
# Я вижу вывод, сообщаю вам что всё запустилось (или где ошибка)
Пример 2: Запуск в фоне

Я могу запустить длительную команду в фоне (например, dev-сервер) и продолжить с вами разговор, пока она работает. Когда она завершится — получу уведомление.

Таймаут: Обычная команда работает до 2 минут. Если нужно больше — я ставлю таймаут до 10 минут. Очень долгие задачи запускаю в фоне.

4.Поиск: Grep и Glob

Grep — поиск текста в файлах

Ищет текст или регулярное выражение по содержимому файлов. Намного мощнее, чем Ctrl+F в редакторе — ищет сразу по всему проекту.

  • Поддерживает регулярные выражения
  • Можно фильтровать по типу файлов (*.py, *.ts)
  • Показывает строки с контекстом вокруг
  • Умеет искать без учёта регистра
Пример

Вы: "Где в проекте используется функция sendEmail?"
Я ищу sendEmail по всем .py файлам и показываю вам все места с номерами строк.

Glob — поиск файлов по имени

Находит файлы по шаблону имени. Работает на любой размер проекта, результаты отсортированы по дате изменения.

Примеры шаблонов
src/**/*.tsx        — все TypeScript React-файлы в папке src
**/*.test.js        — все тестовые файлы
config/*.{json,yaml} — все конфиги в папке config

5.Интернет: WebSearch и WebFetch

WebSearch — поиск в интернете

Ищет актуальную информацию в интернете. Это важно, потому что мои знания имеют дату отсечения (август 2025), а интернет — живой. Я использую поиск когда нужно:

  • Найти актуальную документацию по библиотеке
  • Проверить последнюю версию пакета
  • Найти решение конкретной ошибки
  • Изучить новую технологию

WebFetch — загрузить конкретную страницу

Открывает URL и читает его содержимое. Конвертирует HTML в текст для удобства. Работает с публичными страницами (не требующими входа).

Пример

Вы: "Посмотри документацию React Router v7 и напиши мне пример роутинга"
Я загружаю страницу документации, читаю актуальные API, пишу рабочий пример.

Ограничение: WebFetch не работает с приватными страницами (Google Docs, Confluence, закрытые GitHub-репозитории). Для них нужны специальные интеграции.

6.Подагенты — когда задача слишком большая

Agent — запустить специализированного помощника

Когда задача слишком большая или требует параллельной работы, я могу запустить одного или нескольких подагентов. Каждый — это отдельный Claude с конкретной специализацией. Они работают независимо и возвращают мне результат.

Explore

Быстрый агент только для чтения. Ищет по большой кодовой базе, находит файлы и символы.

Plan

Агент-архитектор. Анализирует задачу, предлагает стратегию, выявляет риски.

general-purpose

Универсальный агент для исследования сложных вопросов и многошаговых задач.

vercel:*

Специалисты по деплою, производительности, AI-архитектуре на платформе Vercel.

Когда я запускаю подагентов

Вы: "Проверь весь проект на проблемы с безопасностью"
Я запускаю Explore-агента для поиска по всем файлам, параллельно — агента для проверки зависимостей. Это быстрее, чем делать всё последовательно самому.

Важно для чайника: Подагенты запускаются от вашего имени и имеют те же права. Я не использую их без необходимости — запуск агента это дорогая операция, поэтому стараюсь делать задачи сам.

7.Git и GitHub

Я умею полноценно работать с Git и GitHub через командную строку. Это одна из моих самых частых задач.

Что я умею с Git

  • Смотреть статус, историю, разницу: git status, git log, git diff
  • Создавать ветки, переключаться, мерджить
  • Делать коммиты с осмысленными сообщениями
  • Разрешать конфликты слияния
  • Работать с тегами и релизами

Что я умею с GitHub (через gh CLI)

  • Создавать Pull Request с описанием и чеклистом тестирования
  • Просматривать и комментировать PR и Issues
  • Читать содержимое репозитория через API
  • Работать с GitHub Actions и релизами
  • Изменять файлы прямо в репозитории (именно так обновлено это эссе)
Пример: как я обновил это эссе
# 1. Получил текущий файл через GitHub API
gh api repos/egorify/claude-code-essay/contents/essay.html

# 2. Написал новый HTML

# 3. Закодировал в base64 и отправил через API
gh api repos/.../contents/essay.html \
  --method PUT \
  --field message="Update essay" \
  --field content="$(base64 новый_файл.html)"
Безопасность: Деструктивные команды (force push, reset --hard, удаление веток) я никогда не делаю без явного разрешения. Спрошу прежде чем что-то необратимое.

8.Фоновые задачи и расписание

TaskCreate / TaskUpdate / TaskList — управление задачами

Для больших задач я разбиваю работу на шаги и отслеживаю прогресс. Это помогает не потерять нить при долгой работе.

  • TaskCreate — создать задачу с описанием
  • TaskUpdate — обновить статус (in_progress → completed)
  • TaskList — посмотреть все задачи
  • TaskOutput — получить вывод задачи
  • TaskStop — остановить задачу

CronCreate / CronList / CronDelete — расписание

Позволяет создавать повторяющиеся задачи по расписанию (cron). Например: каждый день в 9:00 проверять обновления зависимостей и присылать отчёт.

ScheduleWakeup — отложенное действие

В режиме /loop я могу сам решать, когда "проснуться" и продолжить работу. Например, запустил деплой, жду 5 минут, проверяю статус.

Monitor — ждать события

Следит за выводом запущенного процесса и уведомляет меня, когда что-то важное произошло (например, сервер запустился или тест упал).

EnterWorktree / ExitWorktree — изолированная копия

Создаёт временную изолированную копию git-репозитория. Полезно для экспериментов: могу пробовать изменения, не затрагивая вашу рабочую ветку.

10.Память между сессиями

Я помню информацию между разговорами — сохраняю её в файлы на вашем компьютере в папке ~/.claude/projects/.../memory/.

Что я запоминаю

user

Кто вы: профессия, уровень, предпочтения. Чтобы объяснять на вашем уровне.

Пример: "Пользователь — дата-сайентист, слабо знает фронтенд"

feedback

Как вам нравится работать со мной: что делать, что не делать.

Пример: "Не писать длинные резюме после каждого ответа"

project

Контекст проектов: цели, дедлайны, решения, причины.

Пример: "Рефакторинг auth из-за требований compliance"

reference

Ссылки на внешние системы: где баги, где документация, какой дашборд смотреть.

Пример: "Баги трекаются в Linear проекте INGEST"

Попробуйте прямо сейчас: Скажите мне что-нибудь важное о себе или своём проекте — я запомню это и буду знать в следующий раз. Например: "Запомни, что я делаю стартап в сфере EdTech и предпочитаю Python."

Что я НЕ сохраняю в память

  • Структуру кода и архитектуру — её лучше читать из самого кода
  • Историю git — для этого есть git log
  • Временные задачи текущего разговора
  • То, что уже описано в CLAUDE.md вашего проекта

12.Безопасность и ограничения

Что я никогда не делаю без разрешения

  • Force push в Git — можно потерять чужую работу
  • Удаление файлов и папок — особенно если не уверен что они временные
  • Push в main/master — это публичное действие
  • Отправка сообщений (Slack, email, GitHub комментарии)
  • Изменение CI/CD и production-конфигурации
  • Работа с секретами и паролями — никогда не сохраняю их в память или файлы

Что я не делаю принципиально

  • Не генерирую вредоносный код (вирусы, малварь, DoS-атаки)
  • Не помогаю обходить системы безопасности без явного контекста (пентест, CTF)
  • Не выполняю команды с --no-verify или --no-gpg-sign — не обхожу хуки
  • Не сохраняю .env файлы и секреты в Git
Принцип "семь раз отмерь": Если действие необратимо (удаление, force push, сообщение в Slack) — я остановлюсь и спрошу вас, даже если вы не просили. Цена паузы низкая, цена ошибки — высокая.

13.Реальные примеры из жизни

Сценарий 1: "Сделай мне сайт-визитку"

Что произойдёт
  1. Уточню: какой стиль, что написать, нужен ли деплой
  2. Создам index.html, style.css, script.js
  3. Запущу локальный сервер через Bash, проверю что всё открывается
  4. Если нужно — задеплою на Vercel за 2 минуты

Сценарий 2: "Найди баг — приложение падает при регистрации"

Что произойдёт
  1. Прочитаю файлы, связанные с регистрацией
  2. Поищу Grep-ом по ключевым словам (register, signup, user)
  3. Найду проблему, объясню причину
  4. Исправлю и запущу тесты чтобы убедиться

Сценарий 3: "Переведи мой проект с JavaScript на TypeScript"

Что произойдёт
  1. Найду все .js файлы через Glob
  2. Настрою tsconfig.json
  3. Конвертирую файлы по одному, добавлю типы
  4. Запущу tsc — проверю что ошибок нет
  5. Создам коммит с понятным сообщением

Сценарий 4: "Сделай Telegram-бота который отвечает на голосовые"

Что произойдёт
  1. Создам проект: bot.py, requirements.txt, .env.example
  2. Голос → Whisper (транскрипция) → Claude (ответ) → Telegram
  3. Установлю зависимости через Bash
  4. Объясню что нужно для запуска (токены)

Сценарий 5: "Проверь безопасность моего API"

Что произойдёт
  1. Запущу /security-review
  2. Поищу SQL-инъекции, XSS, небезопасную обработку данных
  3. Проверю зависимости на известные уязвимости
  4. Дам список находок с оценкой серьёзности и способами исправления

14.Итог: что я такое

Claude Code — это не просто чат-бот, который отвечает на вопросы. Это агент, который реально работает с вашим компьютером и проектами.

Я читаю и пишу файлы. Запускаю команды. Ищу по коду и интернету. Работаю с Git и GitHub. Запоминаю кто вы и что важно для вашего проекта. Могу запускать других специализированных AI-агентов для сложных задач. Умею деплоить, проверять безопасность, делать ревью кода.
